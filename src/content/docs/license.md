## 一句话

**代码采用 [AGPL-3.0](https://www.gnu.org/licenses/agpl-3.0.html)；
商业闭源使用需单独购买商业授权。**

## AGPL-3.0 对你意味着什么

| 你的用法 | 需要开源吗 | 需要付费吗 |
|---|---|---|
| 自己用 / 家里用 | ❌ 不需要 | ❌ 免费 |
| 公司内部用（不对外） | ❌ 不需要 | ❌ 免费 |
| 修改后**分发**给别人 | ✅ 需要 | ❌ 免费 |
| 修改后**对外提供网络服务**（SaaS） | ✅ 需要 | ❌ 免费 |
| 集成进**闭源产品** | —— | ✅ **需要商业授权** |
| **私有化部署**且不愿开源 | —— | ✅ **需要商业授权** |

> **关键：AGPL 只在「分发」或「对外提供服务」时触发。**
> 内部自用、自己改着玩，完全不受影响。

## 为什么选 AGPL 而不是 MIT

| | MIT | AGPL-3.0 |
|---|---|---|
| 别人能白嫖做闭源 SaaS 吗 | ✅ 能 | ❌ 不能（必须开源） |
| 生态友好度 | 高 | 中 |
| 商业变现能力 | 弱（只能卖服务） | **强（双许可）** |
| 代表项目 | Vue、React | 1Panel、Grafana、MongoDB |

**如果你希望「别人用了你的东西必须回馈社区」，选 AGPL。**
**如果你只想「被尽可能多人用」，选 MIT。**

这个项目选了 **AGPL + 商业双许可**，因为：
1. 整理 NAS 的代码有真实商业价值（NAS 厂商、相册应用）
2. 但个人用户必须能免费用，否则没人装
3. 双许可同时满足这两点

## 商业授权包含什么

| 项 | 内容 |
|---|---|
| 授权范围 | 指定公司 / 指定产品 |
| 权利 | 闭源使用、修改、分发 |
| 期限 | 年度订阅（可续） |
| 支持 | 见[定价](/pricing/) |
| 报价 | 联系作者 |
